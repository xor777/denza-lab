## Команды

Путь: **MyCar → BYDAutoBodyworkDevice → BYDAutoDeviceManager → native
`autoservice` (`android.gui.BYDAutoServer`) → автомобильный HAL**.
Отправитель прототипа — ADB shell. Доступ из обычного UID приложения здесь не проверялся.

| Окно | CLI-ключ | device | FID SET (hex) | FID SET (decimal) |
| --- | --- | --- | --- | --- |
| Переднее левое | `fl` | 1001 | `0x43100038` | 1125122104 |
| Переднее правое | `fr` | 1001 | `0x4310003B` | 1125122107 |
| Заднее левое | `rl` | 1001 | `0x43100040` | 1125122112 |
| Заднее правое | `rr` | 1001 | `0x43100043` | 1125122115 |

`1` — полностью открыть, `2` — полностью закрыть, `3` — остановить.
В штатном enum есть также `5` («проветрить»); в прототип он не включён.
Это команды движения, а не запись процента или постоянной настройки.

Пример формата, **не команда чтения** — открыть переднее левое:

```sh
adb -s 127.0.0.1:5555 shell service call autoservice 6 i32 1001 i32 1125122104 i32 1 null
```

Последний `null` — callback Binder. Его нельзя опускать или заменять массивом
чисел. Используются только транзакции 5 (GET) и 6 (SET int), никаких
array-транзакций: неверный parcel раньше уже ронял autoservice, см.
[Binder](vehicle-data-findings.md#binder).

## Чтение

Все поля ниже — `service call autoservice 5 i32 1001 i32 <fid>`.

| Окно | Процент GET | Инициализация GET | Термозащита GET |
| --- | --- | --- | --- |
| FL | 947912728 (`0x38800018`) | 1222639632 | 1222639646 |
| FR | 1267728400 (`0x4B900010`) | 1267728392 | 947912768 |
| RL | 947912736 (`0x38800020`) | 1222639634 | 1222639647 |
| RR | 947912752 (`0x38800030`) | 1222639638 | 947912769 |

`0%` — закрыто, `100%` — открыто. MyCar классифицирует `≤3` как закрыто,
`>96` как открыто (`l/e/r/l0/i/p/a.java:j`); пульт показывает точные проценты.
Инициализация: `1` — готово, `2` — требуется обучение, `0` — неизвестно.
Термозащита: `1` — активна; снимок всех четырёх показал `0`.
Общее разрешение `BODYWORK_LEFT_FRONT_WINDOW_PERMIT` = `1222639670`:
`0` — разрешено, `1` — запрещено (`WINDOW_ENABLE/WINDOW_DISABLE` в framework).

Снимок 2026-10-16: P=1, permit=0, все init=1, все thermal=0;
FL=100%, FR/RL/RR=0%. Это live-проверка чтения, без команд движения.

## Прототип

Только стандартная библиотека Python 3 и установленный `adb`:

```sh
python3 tools/vehicle_windows.py status
python3 tools/vehicle_windows.py serve
# Другой уже подключённый транспорт:
python3 tools/vehicle_windows.py serve --serial 127.0.0.1:5555 --port 8769
```

Открыть **полную** напечатанную ссылку с фрагментом после `#`. Сервер слушает
только `127.0.0.1`, требует случайный токен для API и проверяет Host/Origin.
Выключение: Ctrl-C. Закрытие страницы или сервера не отправляет команд машине.

- При запуске сравнивает MyCar/framework по SHA-256 и требует CANFD, тип 168/170.
  Смена `boot_id` запрещает команды до перезапуска пульта и повторной проверки.
- Кнопки пишут только в четыре указанных FID. Нет общего исполнителя команд,
  кнопки «все окна», изменения защиты/обучения или фоновых сценариев.
- Перед open/close заново читает P, разрешение, init, thermal и положение.
  Неизвестное значение запрещает движение. Ограничение P — правило этого
  прототипа, не утверждение о требовании штатного приложения.
- STOP проверяет идентичность подключения, но не блокируется P или защитами.
- Один ADB-запрос одновременно; занятый пульт отклоняет действие, не ставит
  его в очередь. Запись отправляется один раз. Тайм-аут — неизвестный исход,
  а не доказательство, что команда не дошла.
- Чтение раз в 2 секунды только при видимой странице; устаревшие данные скрываются.
  После команды отдельный GET обновляет положение, без оптимистического «закрыто».
- `captures/window-control/actions.jsonl` сохраняет попытку до SET и ответ после.
  Удаление окна браузера не закрывает автомобильные окна.

Проверки без автомобиля:

```sh
python3 -m unittest discover -s tools -p test_vehicle_windows.py -v
```

11 тестов: точные команды, ошибочные parcels, native однословный SET, отсутствие повторов,
блокировки на свежих чтениях, доступность STOP, смена машины/загрузки,
проверка хешей, HTTP-доступ и отсутствие записей через GET.

## Проверка на машине

Для первого физического цикла владелец находится у машины, окна свободны,
одна сессия владеет управлением. Зафиксировать начальные проценты. Нажать
«Открыть» у одного закрытого окна, затем «Стоп» в движении, сверить остановку
глазу и проценты, затем «Закрыть» и сверить возврат к исходному положению.
Не отправлять повторные команды при тайм-ауте; сначала проверить стекло.

> **Superseded 2026-10-16:** первоначальный парсер ожидал два слова и код 0.
> Native SET отвечает одним словом HAL, `1` означает принятую команду. Исправлены
> парсер, сообщение UI и тест; ранние записи журнала сохранены без переписывания.

В журнале первых владельческих нажатий: FL close/open и FR close/open
вернули `Result: Parcel(00000001    '....')`. Старый парсер помечал эти ответы
как неопределённые. Владелец затем написал «отлично» и запросил расширение пульта;
это не отдельное подтверждение движения/STOP каждого стекла.

Предсказание: SET отвечает кодом 1, процент растёт при открытии, после STOP
перестаёт изменяться, при закрытии падает к 0. Отрицательный код, отсутствие
движения при коде 1, несовпадение окна или направления опровергает эту цепочку
для данного автомобиля; сохранить журнал и не продолжать серию на других окнах.
Полная пооконная приёмка остаётся открытой.

## Расширенный пульт

```sh
python3 tools/vehicle_control.py status
python3 tools/vehicle_control.py serve --serial 127.0.0.1:5555 --port 8769
python3 -m unittest discover -s tools -p 'test_vehicle_control.py' -v
python3 -m unittest discover -s tools -p 'test_vehicle_windows.py' -v
```

`vehicle_windows.py` остаётся транспортом и самостоятельным пультом окон.
`vehicle_control.py` добавляет конечный список контролов из
`vehicle_controls.json`. Каталог содержит именованные свойства, device, реальные
CANFD FID, тип GET, конфигурацию и соответствие действия значению. Клиент не может
задавать произвольный FID, shell-команду, длительность импульса или уровень 6.

Расширенный сервер требует N9/168, хеши MyCar/framework из предыдущего раздела
и `/system/priv-app/DiCarServer/DiCarServer.apk`:
`ef8dc5e45f555633b4476637a05560522534a605e79d9d5b70df5c55caf142d6`.
Все три совпали с машиной. DiCarServer: `3.2.0-beta.1-20260603 (5)`.
Основные источники — прежний MyCar и
`captures/ambient-light-20260923/jadx/DiCarServer/sources/com/byd/car/feature/seat/`:
`property/AdjustmentKeys.java`, `AdjustmentValues.java`, `VentHeatKeys.java`,
`VentHeatValues.java`, `CarSeatAdjustmentServiceImpl.java`.
Числовые значения взяты из `fids-canfd.tsv` и CANFD ветвей
`framework/.../BYDAutoFeatureIds.java`; строковые hex-ключи DiCar не подменяют FID.

Опрос раз в 4 секунды только в видимой вкладке; через 10 секунд без успешного
чтения показания скрываются. Действие ждёт завершения одного текущего чтения UI,
затем сервер повторно читает защиты; повторные нажатия во время записи не отправляются.
Сервер сериализует ADB, отклоняя конкурирующие запросы кодом 409 без очереди.
Для штатных регуляторов/ЭБУ это отдельный владелец управляющей сессии:
одновременно не двигать те же механизмы другим пультом или штатным экраном.

26 локальных тестов (11 окна + 15 новые): точные значения и FID, потерянные ответы,
защиты, проверка профиля, отсутствие записей при чтении, ошибки/неизвестная
комплектация, восстановление блокировки после перезапуска. Реальный `/bin/sh`
с подставными командами проверяет STOP после ошибочного старта и TERM;
это не аппаратная приёмка Android/ECU.

UI проверен в браузере на реальных GET: окна, центральный замок/четыре двери,
водительское кресло, третий ряд (без вентиляции, недостоверные оси отключены).
На отдельном fake-сервере пройден клик шага с HAL-отказом STOP и ручной STOP:
блокировка, отдельная кнопка восстановления и снятие блокировки видны в UI.
Журнал этой проверки лежит отдельно в `captures/window-control-20261016/ui-test/`.
При подготовке пульта агент отправлял новые действия только fake-серверу.
Первые записи от нажатий владельца на live пульт отмечены ниже.

## Сиденья

`AdjustmentValues.ServiceValues`: направленные регуляторы передают
`1` вперёд/вверх, `2` назад/вниз, `0` отпустить/стоп. Все приведённые SET —
device1023, transaction6. FID по рядам:

| Кресло | Продольно | Спинка | Высота | Наклон подушки | Опора для ног |
| --- | --- | --- | --- | --- | --- |
| FL | 1276137488 | 1276137492 | 1276137490 | 1276137494 | 1276137523 |
| FR | 1276137496 | 1276137500 | 1276137498 | 1276137502 | 1276137510 |
| RL | 1276186652 | 1276186656 | — | — | 1276186660 |
| RR | 1276186664 | 1276186668 | — | — | 1276186672 |
| 3-й ряд L | 850411536 | 850411540 | — | 850411542 | — |
| 3-й ряд R | 850411548 | 850411552 | — | 850411554 | — |

Таблица показывает 22 оси с подтверждёнными конфигурацией, init и положением.
Наличие реального движения не доказано чтением. Полный исследованный каталог
включает и другие оси, но они заблокированы. У передних кресел
electric config=3 даёт продольно/спинку/высоту/подушку; у остальных config=1
для конкретной оси означает наличие. Позиция — GET float transaction7,
диапазон 0..100. `127.5`, отрицательные, NaN/Inf — не положение.
Для каждого разрешённого шага требуется свежий P=1, поддержка, позиция и init=1.
У ряда 3 конфигурация нескольких дополнительных осей сообщает 1, но положение
127.5 и отсутствие init не позволяют включить их кнопки.

Один клик запускает на Android shell последовательность «направление → sleep0.3 →
STOP». STOP стоит в EXIT trap; HUP/INT/TERM завершают скрипт через этот trap.
Закрытие браузера не является таймером остановки. START никогда не повторяется.
Оба raw ответа сохраняются; если STOP не подтверждён, новые движения кресел
блокируются до ручного STOP с HAL=1. Блокировка восстанавливается из журнала
после перезапуска сервера. SIGKILL, остановка ОС/ЭБУ и зависший Binder не дают
гарантии физической остановки: 0.3 секунды — длина команды, не измеренное движение.

| FR | 1125122076 | 1125122072 |

В UI уровни `0/1/2/3`, SET обычно `1/2/3/4`; исключение — **обогрев водителя
уровень 3 передаёт 6**, как `VentHeatValues.getPropertyValues(4096,16,3)`.

обогревов и первых четырёх вентиляций. Все были выключены (GET=1).

## Приёмка новых контролов

Исходное состояние — сохранённый снимок, P, соответствующий механизм свободен,
владелец рядом; одна управляющая сессия. Для замка сверить запирание и обратный
unlock, для одной двери open/STOP/close, для одной оси один короткий шаг и
остановку, для комфорта уровень1 и выкл. Каждое действие отдельное, без пакета
по всем креслам или дверям. Сохранить фактические наблюдения рядом с журналом.
HAL=1 предсказывает принятие; положение должно измениться только у выбранной
оси/двери и перестать меняться после STOP. Комфорт GET должен перейти в выбранный
уровень. Другой механизм, направление, отказ остановки или тайм-аут опровергают
текущий контракт: не продолжать серию и не переотправлять START автоматически.
