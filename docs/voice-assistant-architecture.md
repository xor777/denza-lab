# Голосовой помощник: архитектура

Предложение архитектуры офлайн-голосового помощника для Denza Apps на головном
устройстве (DiLink 5.1, Android 13). Кода пока нет. Документ — задание для
разработки и опись того, что о машине уже известно, а что ещё предстоит проверить.

**Open questions**

- Пишет ли скрытое приложение микрофон по кнопке без глушения? Ответ даст пробник:
  служба переднего плана типа `microphone`, запущенная из фона, режим
  `appops RECORD_AUDIO`, флаг silenced в `dumpsys audio`.
- Какой источник — `MIC`, `VOICE_RECOGNITION` или `VOICE_COMMUNICATION` — проходит
  эхо- и шумоподавление салона? Ответ дадут записи пробника при играющей музыке и
  чтение `BydAutoVoice` и `audio_policy_configuration.xml` в корпусе прошивки.
- Сколько стоят модели на CPU головного устройства? Ответ даст прогон записей
  пробником: RTF, пиковая RSS, время загрузки.
- Как делить кнопку между помощником и Алисой? Это решение владельца.
- Где FID климата? Ответ дадут корпус (MyCar и климатическое приложение) и чтение
  через GET.
- Работает ли `ask_alice` с непустым текстом? Ответ даст один запуск при владельце.
- Есть ли на головном устройстве системный синтез речи с русским голосом? Ответ
  даст список установленных движков TTS.

## Требования

- Работает офлайн, на самом головном устройстве. Сеть нужна только для того,
  чтобы передать Алисе фразы не про машину.
- Понимает русский и английский.
- Разбирает несколько команд в одной фразе, включая общий глагол («открой
  водительское и пассажирское») и общее значение («подогрев руля и сидений на
  тройку»).
- Лёгкий: пока кнопку не нажали, процессор не занят; во время команды — около
  одного ядра на пару секунд; память — сотни мегабайт, а не гигабайты.
- Управляет машиной (окна, двери, кресла, шторки, свет, позже климат) и
  функциями Denza Apps.

## Что уже есть

Платформа: DiLink 5.1, Android 13 (API 33), SoC MediaTek. Denza Apps
(`dev.denza.apps`) получает права shell через локальный ADB
([adb-authorization-recovery.md](adb-authorization-recovery.md)).

- **Кнопка.** Кнопка голоса на руле — keycode 320 (`KEYCODE_AUTO_MEDIA_VOICE`,
  scanCode 290). Прошивка отдаёт её фильтру клавиш accessibility раньше, чем
  штатному ассистенту. Общий a11y-сервис продукта уже поглощает её в
  [AliceVoiceKeyRider.kt](../apps/denza-apps/src/main/java/dev/denza/apps/feature/alice/AliceVoiceKeyRider.kt)
  и открывает Алису, когда Навигатор виден
  ([shortcuts-automation-findings.md](shortcuts-automation-findings.md#alice-in-yandex-navigator-2026-10-11)).
- **Микрофон.** Штатный ассистент постоянно держит встроенный микрофон на
  `VOICE_RECOGNITION` ([audio-capture-findings.md](audio-capture-findings.md#permissions)).
  Навигатор, обычное приложение, рядом с ним получал несглушённый `MIC`, но был
  при этом на экране.
- **Исполнитель.** Продукт ходит в `autoservice` через локальный ADB shell
  ([AutoserviceShell.kt](../apps/denza-apps/src/main/java/dev/denza/apps/feature/vehicle/AutoserviceShell.kt));
  приборка читает его по белому списку FID
  ([VehicleSignals.kt](../apps/denza-apps/src/main/java/dev/denza/apps/feature/vehicle/VehicleSignals.kt)).
  Допустимы только транзакции 5 (GET) и 6 (SET int): неверно собранный parcel
  уже ронял сервис ([vehicle-data-findings.md](vehicle-data-findings.md#binder)).
  FID окон, замков, дверей, кресел, шторок и света собраны в
  [window-control-findings.md](window-control-findings.md) и
  [tools/vehicle_controls.json](../tools/vehicle_controls.json).
- **Алиса.** По коду Навигатора 29.8.1 `yandexnavi://ask_alice?text=<текст>`
  отправляет Алисе текстовый запрос
  ([shortcuts-automation-findings.md](shortcuts-automation-findings.md#why-the-deep-link-is-only-half-an-answer)).

## Конвейер

```
кнопка голоса на руле (keycode 320)
 → AudioRecord 16 кГц моно + AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE (музыка на паузе)
 → Silero VAD: фраза закончилась после ~0,6 с тишины
 → ASR ru ‖ ASR en: параллельно, потоково, словарь каталога как подсказка
 → парсер: фраза → список кадров {действие, объект, значение}
 → проверка: поддерживается ли, диапазон, безопасность (скорость, передача)
 → исполнитель: AutoserviceShell по белому списку; действия приложения
 → отклик: само действие + короткий звук + строка на экране
   └ не про машину («поехали домой», «найди заправку») → текстом в Алису
```

Голосовой движок работает в отдельном процессе (`:voice`), чтобы падение
нативной библиотеки не роняло приборку. Модели лежат вне APK, в файлах
приложения, и при загрузке сверяются по SHA-256.

## Звенья и технологии

### Запуск

> **Дополнено 2026-10-16:** кнопка ниже — исходный вариант прототипа.
> Владелец запросил активацию голосом со всех пассажирских мест. Штатный
> многозонный тракт, ограничения его callback и предложение своего KWS описаны
> в [исследовании активации](voice-assistant-activation.md). Для такого режима
> нужен постоянный лёгкий детектор; «ноль CPU до кнопки» к нему не относится.

Кнопкой, без слова активации. Нажал и говоришь: пока кнопку не нажали,
процессор не занят, случайных срабатываний нет. Штатный ассистент и так слушает
постоянно; использование его тракта требует отдельной проверки интерфейсов.

Сейчас кнопка отдана Алисе, когда Навигатор виден. Как её делить — решение
владельца. Предлагаемый вариант: кнопка запускает помощника, а всё, что он не
распознал как команду машине, уходит в Алису (см. [Запасной путь](#запасной-путь)).

### Звук

Эхоподавление на старте не нужно: пока помощник слушает, он забирает аудиофокус
(`AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`), и музыка встаёт на паузу. Источник
звука выбирается по записям пробника.

Будет ли звук, когда Denza Apps скрыт, пока неизвестно. Варианты, которые
проверяет пробник:

- служба переднего плана типа `microphone`;
- режим `appops RECORD_AUDIO` через shell;
- окно, открытое из a11y-сервиса: Android разрешает привязанному
  AccessibilityService запускать активности из фона.

### Распознавание

Основа — [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), один набор
инструментов под Android (Kotlin API, Apache 2.0): VAD, потоковое распознавание,
подсказка словаря (hotwords для transducer-моделей), поиск ключевых слов, синтез
речи.

- **Русский.** Две потоковые модели на сравнение: Vosk streaming zipformer small
  (int8) и T-one (70M параметров, Apache 2.0, обучена на телефонных разговорах).
- **Английский.** Маленький streaming zipformer.
- **Быстрый прототип.** Vosk в режиме грамматики; русская small-модель весит 45 МБ.
- **Если не хватит точности на русском,** готовую фразу можно прогнать вторым
  проходом через GigaAM-v3. Начинать без него.

Не берём:

- **Whisper:** не потоковый, на коротких командах выдумывает текст, маленькие
  версии слабы в русском.
- **Языковую модель в основном пути:** на порядок тяжелее и медленнее, может
  «придумать» команду.

Лицензии весов GigaAM-v3, моделей Vosk и голосов Piper сверить до
распространения сборки.

### Два языка

Оба распознавателя слушают одну и ту же запись в 2–4 секунды. Побеждает текст,
который парсер разобрал целиком, так что парсер заодно определяет язык. При
равенстве решает уверенность распознавателя. Латинские названия лежат в русском
словаре так, как их произносят («спотифай», «ютуб»).

### Отклик

- Подтверждение — само действие, короткий звук и строка на экране.
- Голосом — только ответы на вопросы о состоянии («сколько заряда?»), из тех же
  данных, что показывает приборка.
- Синтез речи — системный, если на головном устройстве есть русский голос, иначе
  Piper через sherpa-onnx.
- Если помощник не уверен, он показывает 2–3 варианта, которые можно выбрать
  нажатием, а не говорит «я не понял».

## Несколько команд в одной фразе

Задача не в том, чтобы найти одну команду во фразе, а в том, чтобы разобрать
фразу в список кадров. Разбор идёт в четыре шага:

1. **Нормализация.** Нижний регистр; числа словами → числа («двадцать два» → 22,
   «на тройку» → 3, «наполовину» → 50 %); слова-паразиты убираются
   («пожалуйста», «слушай», «давай»).
2. **Разметка.** Ищется самое длинное совпадение со словарём каталога
   (многословные имена вроде «подогрев руля»). Каждая лексема получает роль:
   действие, объект, значение или связка.
3. **Сборка кадров** по грамматике `фраза := команда (связка команда)*` со
   связками «и», «а», «потом», «ещё», «and», «then» и по правилам ниже. Если
   правил станет много — chart-парсер (алгоритм Эрли), который выбирает разбор с
   наибольшим покрытием слов.
4. **Раскрытие и проверка.** Группы раскрываются в отдельные объекты, каждый кадр
   сверяется с каталогом, собирается план исполнения.

```
«закрой окна и включи подогрев руля и сидений на тройку а музыку потише»

разметка  [закрой]Д [окна]О и [включи]Д [подогрев руля]О и [сидений]О [на 3]З
          а [музыку]О [потише]Д              (Д действие, О объект, З значение)
кадры     close{окна} | on{подогрев.руль, подогрев.сиденья} level=3 | volume−{музыка}
команды   close FL FR RL RR · on руль · сиденье.вод=3 · сиденье.пасс=3 · громкость −1
```

Правила:

- **Новое действие начинает новый кадр.** «И» плюс объект, подходящий к текущему
  действию, остаются в том же кадре («руля и сидений»). Кадр без глагола берёт
  его у соседа («открой водительское и пассажирское»).
- **Значение достаётся только объектам, которые его принимают** (тип записан в
  каталоге). Если у руля нет уровней, «на тройку» уходит сиденьям; градусы идут
  климату, проценты — окнам и шторкам.
- **Группы раскрывает каталог:** «окна» — это 4 окна, «передние» — 2, «сиденья»
  без уточнения — водитель и пассажир.
- **Поправки:** в «открой… нет, закрой» побеждает последнее; противоречащие
  команды одному объекту схлопываются.
- **Относительные значения** («потеплее», «ещё», «на два градуса») считаются при
  исполнении от текущего состояния машины, а не в парсере.
- **Короткие продолжения** («и заднее тоже», «ещё») в течение ~10 с после
  команды достраиваются по её кадрам.
- **Главный сигнал — покрытие.** Если значимые слова остались неразобранными,
  фраза уходит в запасной путь, а не исполняется наполовину.
- **У каждого кадра свой результат.** «Окна закрыл, люк на ходу не открою» —
  частичный успех, а не ошибка.

Выход парсера — список кадров, общий для обоих языков:

```json
[
  {"action": "close",  "target": "window.fl"},
  {"action": "on",     "target": "wheel_heat"},
  {"action": "set",    "target": "seat_heat.driver", "value": 3},
  {"action": "adjust", "target": "media.volume", "delta": -1}
]
```

Словоформы (окно, окна, окон) заранее генерируются на компьютере через pymorphy3
в готовую таблицу; на машине остаётся только поиск по ней. Ошибки распознавания
сглаживает нечёткое сравнение слов. Английский словарь собирается из того же
каталога и даёт те же кадры.

## Запасной путь

- **Фразы про машину вне грамматики** («мне душно»). Модель нужна, только если
  логи покажут, что такие фразы встречаются. Тогда подойдёт крошечная модель,
  дообученная на фразах, сгенерированных той же грамматикой: FunctionGemma 270M
  (вызов функций, ~0,3 ГБ на диске) или разметчик слов на rubert-tiny2 (~30 МБ в
  int8). Её вывод жёстко ограничен схемой каталога: она выдаёт только кадры.
  Загружается по требованию.
- **Фразы не про машину** («поехали домой», «найди заправку») уходят в Алису
  текстом через `yandexnavi://ask_alice?text=<текст>`. По коду Навигатора это
  текстовый запрос; вживую проверен только запуск с пустым текстом.

## Безопасность исполнения

- Ни парсер, ни модель не выдают FID — только кадры из перечня в каталоге. FID
  знает только исполнитель.
- Исполнитель переводит кадры по белому списку, тем же путём, что
  `AutoserviceShell`, и только транзакциями 5 и 6.
- Ограничения по скорости и передаче (двери, багажник, люк на ходу) записаны в
  каталоге и проверяются до записи.
- Перед относительным изменением исполнитель читает текущее значение через GET.
- Каждый кадр возвращает свой результат; отказ по одному кадру не отменяет
  остальные.

## Ресурсы

Оценки порядка величин, не замеры. Цифры даст пробник.

| Звено | Диск | Память | Процессор |
| --- | --- | --- | --- |
| Кнопка, парсер, исполнитель | ~0 | ~0 | < 1 мс |
| Silero VAD | ~2 МБ | ~20 МБ | доля ядра, только пока слушает |
| Распознавание ru + en (int8) | десятки МБ на язык | ~100–200 МБ на язык | ~1 ядро на 2–4 с команды |
| Запасная модель (по желанию) | 30–300 МБ | до ~0,5 ГБ | ~1 с, загружать по требованию |
| Озвучка ответов (по желанию) | системный синтез речи или Piper ~60 МБ | ~100 МБ | только во время ответа |

Пока кнопку не нажали, процессор не занят. Держать ли модели в памяти или
грузить по нажатию, решит замер времени загрузки.

## Каталог команд

Каталог — единственный источник правды. Для каждого объекта в нём лежат:

- синонимы на двух языках;
- группы («окна», «передние»);
- действия;
- тип и диапазон значений;
- привязка к FID или к действию приложения;
- ограничения безопасности.

Из каталога генерируются:

- подсказки для распознавания;
- словоформы для парсера;
- эталонные тесты «фраза → кадры»;
- обучающие фразы для запасной модели;
- экран «что можно сказать».

Формат — на усмотрение разработки (JSON рядом с `vehicle_controls.json` или
Kotlin DSL). Пример для одного окна; FID и значения взяты из
[window-control-findings.md](window-control-findings.md#команды):

```yaml
window.fl:
  names:
    ru: [переднее левое окно, окно водителя, водительское окно]
    en: [front left window, driver window]
  groups: [windows, front_windows]
  actions:                       # autoservice: device 1001, SET FID 0x43100038
    open:  {tx: 6, device: 1001, fid: 0x43100038, value: 1}
    close: {tx: 6, device: 1001, fid: 0x43100038, value: 2}
    stop:  {tx: 6, device: 1001, fid: 0x43100038, value: 3}
```

Основа уже есть: FID окон, замков, дверей, кресел, шторок и света. FID климата
ещё предстоит найти в прошивке.

## План работ

1. **Пробник** `experiments/voice-probe/` (только под `-Pexperiments`).
   Проверяет захват микрофона, когда приложение скрыто, сравнивает источники
   звука при играющей музыке, замеряет RTF и память моделей на записях из
   машины. Начинается с корпуса: как микрофон берёт `BydAutoVoice`. Готово,
   когда в [audio-capture-findings.md](audio-capture-findings.md) есть ответы на
   первые три открытых вопроса или явное «не проверено».
2. **Каталог и парсер** — чистый Kotlin без Android, с эталонными тестами на двух
   языках: составные фразы, общий глагол, общее значение, поправки, относительные
   значения, слова-паразиты. Ни звук, ни машина не нужны. Готово, когда тесты
   проходят и парсер считает покрытие.
3. **Интеграция** в Denza Apps: процесс `:voice`, кнопка через a11y-сервис,
   исполнитель по белому списку, отклик. Готово после приёмки владельцем на
   машине.
4. **Тест на записях.** Реальные команды, записанные в машине, прогоняются через
   конвейер и сверяются с ожидаемыми кадрами, как в `VehicleLogReplayTest`.
5. **Запасная модель** — только если логи покажут, что она нужна.
