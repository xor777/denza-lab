## Что сравнивается

Отдельный пакет `dev.denza.overseamap.probe` показывает рядом один сохранённый
фрагмент штатной карты: слева без масок (`oversea=false`), справа — с масками
ветки `oversea=true`. Нажатие на вариант выбирает увеличенный вид ниже.
Кнопки меняют только светлую/тёмную маску, а не тему исходного снимка.

Это реконструкция одного слоя оформления **приборки** на снимке с центрального
дисплея. Это не исполнение штатной сцены Godot, не live-карта и не переключение
региона. Источник — `com.byd.launchermap`, а не Яндекс. На снятом кадре карта
в текущем месте не показала картографических деталей; остался указатель машины.
Не подставляются другая местность, искусственные дороги или чужой провайдер.

Приложение содержит только Activity и изображения: без разрешений, сетевого
доступа, служб, receivers, автомобильных API, записи Settings/свойств или
открытия других дисплеев. Единственные состояния — выбор маски и увеличения
в памяти Activity / saved instance state.

## Источники и геометрия

Всё извлечённое и APK остаются git-ignored. Подготовщик проверяет закреплённые
SHA-256 четырёх `.ctex`, сцены, shader и исходного снимка. Прямоугольник снимка
`(744,450)–(2536,954)` исключает панель меню и системные полосы; соотношение
1792×504 совпадает с 2560×720. Кадр не является снимком проекции приборки.

- `drive_map.gd:_slot_ui_layout_changed` задаёт размер MapMask равным wSize;
  в исследуемой ветке wSize = 2560×720. При false текстуры снимаются.
- `drive_map.scn`: MapMask — TextureRect без переопределения stretch_mode;
  исходные центральные текстуры 1920×720 растягиваются до 2560×720.
- MaskLeft занимает x=0…960, MaskRight привязан к правой границе и занимает
  x=1600…2560; обе маски высотой 720. Это **не** две половины по 1280 пикселей.
- `oversea_mask.gdshader` сохраняет alpha, заменяет RGB боковых текстур на
  `#384858` для dark или `#CFDAE5` для light. Центральная текстура сохраняет RGB.
- AVM/PiP-вырез выключен. Иные слои, принудительная тёмная тема поставщика GAS
  и состояния fallback/loading здесь не воспроизводятся.

Pillow накладывает слои по порядку сцены. Проверяются прозрачность середины и
цвета непрозрачных краёв. Это не заявление о пиксельном совпадении с GPU Godot:
интерполяция и цветовой pipeline штатного compositor здесь не выполняются.
`probe-assets-verification.json` хранит входные и выходные хеши, размеры,
геометрию, версии декодера и результаты пиксельных проверок.

## Сборка

Локальные зависимости: `texture2ddecoder==1.0.6`, `Pillow==11.3.0`, установленные
в `captures/oversea-map-probe-20261018/python-deps/` для `.venv-firmware/bin/python`.
Они не входят в APK. Подготовка assets выполняется задачей `prepareAssets`.

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
./gradlew -Pexperiments :oversea-map-probe:assembleDebug
```

Пакет: `build/outputs/apk/debug/oversea-map-probe.apk` относительно этого модуля.
Без локального корпуса сборка завершится ошибкой; заглушки не генерируются.

## Проверка на машине

План перед первой установкой, 2026-10-18:

- Гипотеза: независимая Activity покажет две версии кадра на display 0;
  переключение темы изменит только слой маски справа и в увеличенном виде.
- До запуска: сохранить foreground/display state, прочитать скорость,
  сохранить crash buffer; использовать существующий ADB `127.0.0.1:5555`.
  Предыдущий read-only замер перед открытием карты дал speed=0 и стояночный
  тормоз=1; последнее не доказывает положение селектора P.
- Единственная установка — новый пакет пробника. Не останавливать приложения
  машины, не менять проекцию, не обращаться к vendor controllers.
- Ожидаемый результат: foreground собственного MainActivity на display 0,
  те же данные слева в обеих темах; края справа меняют цвет.
- Reset: кнопка «Закрыть» завершает Activity; предыдущая штатная карта остаётся
  под ней. Для удаления пробника достаточно uninstall его собственного пакета.
- После: снимки обеих тем, проверка увеличения, сравнение crash buffer и
  подтверждение неизменного `persist.sys.AutoType`. При `com.byd.avc` crash
  сохранить `logcat -b crash -v time`, сообщить и не повторять триггер.

## Результат проверки

2026-10-18 APK установлен через существующий transport, `am start -W --display 0`
вернул `Status: ok`. Снимки `probe-dark.png`, `probe-light.png` и
`probe-enlarged-original.png` подтверждают обе темы и увеличение по нажатию.
Пиксели внутренней области левой панели совпали между темами. Код модели
остался 170. Crash buffer полностью совпал с исходным: новых записей нет.
`aapt2 dump permissions` не перечисляет разрешений. `assembleDebug` прошёл,
`lintDebug`: 0 ошибок, 2 предупреждения (backup rules и отсутствующая иконка).
SHA-256 установленного APK по исходному артефакту сборки:
`244a98c00f2ca3d181964e4512bba49184a0be99357fda4249caf2095aa396f8`.

Пользователь уточнил, что ожидал увидеть содержимое карты и изменения её
работы. Показ градиента на статическом пустом кадре **не решает эту задачу**.
Пробник закрыт штатной кнопкой; финальный `topResumedActivity` на display 0 —
`com.byd.launchermap/com.byd.automap.activity.MainActivity`. Пакет оставлен
установленным, но Activity не открыта. Код региона/поставщика карты не менялся;
появление картографических данных не проверялось и не достигнуто.
